# 让其他电脑打开这个网站

> 目标：别的电脑/手机在同一 Wi-Fi 下打开 `http://<你的IP>:8000` 就能用；不需要装 Node、不需要记两个端口。
>
> 核心改动：前端 `npm run build` 后，FastAPI 直接把 `frontend/dist` 挂在 `/` 上，网页和 API 共用 **8000 一个端口**。

---

## 0. 选哪种方式

| 场景 | 方式 | 地址 | 是否需要公网 |
|---|---|---|---|
| 同一 Wi-Fi / 局域网演示 | **单端口（推荐）** | `http://<本机IP>:8000` | 否 |
| 前端要热更新、边改边看 | Vite 开发模式 | `http://<本机IP>:5173` | 否 |
| 异地电脑，但只给自己人 | Tailscale 私有网络 | `http://<tailscale-IP>:8000` | 否（私有） |
| 完全公网、发给别人 | **Cloudflare Quick Tunnel / Pinggy + Basic Auth（3.6，推荐）** | `https://xxx.trycloudflare.com` 或 `https://xxx.pinggy...` | 是 |
| 完全公网、临时无鉴权演示 | Pinggy 直连（3.5，不推荐） | `https://xxx.pinggy...` | 是 |

**医疗数据优先用前两种。** 3.6 的密码版给所有请求加了 HTTP Basic Auth；3.5 的直连版没有登录，任何拿到 URL 的人都能调用 OCR、消耗你的 API 额度，也可能看到页面上的患者数据，只适合合成数据演示。

## 1. 方案 A：单端口（推荐）

### 1.1 原理

```
其他电脑浏览器
   │  http://<你的IP>:8000
   ▼
FastAPI (uvicorn --host 0.0.0.0)
   ├── /            → frontend/dist/index.html
   ├── /assets/*    → dist/assets/*.js / *.css
   ├── /api/analyze → 规则引擎
   ├── /api/ocr     → qwen3-vl-plus
   └── /api/chat    → RAG SSE
```

- 网页和 API 同源，不需要 Vite 代理，也不会有 CORS。
- 只需要开放 **8000** 一个端口。
- 前端改动后要重新 `npm run build`，然后重启后端（或刷新页面，静态文件会重新读）。

### 1.2 一键脚本

项目根目录新增：

```text
scripts/serve_lan.ps1
scripts/serve_lan.bat
```

双击 `scripts\serve_lan.bat`，或在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\serve_lan.ps1
```

脚本会：

1. `cd frontend && npm run build`；
2. 打印本机 IPv4（类似 `http://192.168.1.23:8000`）；
3. `uvicorn api:app --host 0.0.0.0 --port 8000`。

> 如果 8000 已被旧的 uvicorn 占用，先在旧终端按 **Ctrl+C** 停掉。脚本不会杀进程。

### 1.3 手动命令

```powershell
# 1. 构建前端（有改动就重新跑）
cd C:\Users\sakura\pci-med\frontend
npm.cmd run build

# 2. 启动后端，绑定所有网卡
cd ..\backend
.\venv\Scripts\python.exe -m uvicorn api:app --host 0.0.0.0 --port 8000
```

**不要**再用默认的 `uvicorn api:app --reload` 给局域网用：它只绑定 `127.0.0.1`，其他电脑连不上。演示时也建议去掉 `--reload`，避免改文件导致服务重启。

### 1.4 本机自检

浏览器打开：

```
http://127.0.0.1:8000/
http://127.0.0.1:8000/api/health
```

`/api/health` 应返回：

```json
{"ok": true, "web": true}
```

- `ok: true`：API 正常；
- `web: true`：`frontend/dist/index.html` 存在，网页会由后端托管；
- `web: false`：没构建或 `dist` 被删了，回 1.3 重新 build 并重启。

## 2. 找到本机 IP

```powershell
ipconfig
```

看 **Wireless LAN adapter WLAN**（Wi-Fi）或 Ethernet 的 **IPv4 地址**，例如：

```text
IPv4 地址 . . . . . . . . . . . . : 192.168.1.23
```

也可以用：

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object IPAddress, InterfaceAlias
```

可能有多个（Wi-Fi、以太网、虚拟机、VPN）。优先选当前上网的 WLAN/以太网。

## 3. 防火墙（其他电脑连不上，90% 是这里）

需要**管理员** PowerShell：

```powershell
New-NetFirewallRule -DisplayName "PCI-MED 8000" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -Profile Private
```

- `-Profile Private`：只对“专用网络”放行，最安全。
- 如果当前 Wi-Fi 被 Windows 识别为“公用网络”，两种选择：
  - 把网络改成专用（管理员）：
    ```powershell
    Set-NetConnectionProfile -InterfaceAlias "WLAN" -NetworkCategory Private
    ```
  - 或者放行所有网络（不建议在公共 Wi-Fi 用）：
    ```powershell
    New-NetFirewallRule -DisplayName "PCI-MED 8000 Any" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -Profile Any
    ```

图形界面：Windows 安全中心 → 防火墙和网络保护 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP → 特定本地端口 8000 → 允许连接 → 专用/域 → 命名。

Vite 开发模式要放行 **5173**，把上面命令里的 8000 换成 5173。

## 3.5 防火墙改不了 / 没有管理员权限：用出站隧道

如果出现下面这些错误：

```text
New-NetFirewallRule : 拒绝访问
Set-NetConnectionProfile : not running PowerShell elevated
NetworkCategory cannot be changed from 'DomainAuthenticated'
```

说明两件事：

1. 当前 PowerShell **没有以管理员身份运行**，所以建不了防火墙规则；
2. 当前网络是 `DomainAuthenticated`，你用的 `-Profile Private` 规则**对域网络不生效**；`Set-NetConnectionProfile` 又被组策略禁止。

如果你有管理员权限，正确做法是：右键 PowerShell →「以管理员身份运行」，然后：

```powershell
New-NetFirewallRule -DisplayName "PCI-MED 8000" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -Profile Any
```

`-Profile Any`（或 `Domain`）才会覆盖当前的域网络。**不需要**再改 `NetworkCategory`。

如果组策略仍然禁止、或者你根本没有管理员密码，**不要继续折腾防火墙**，直接用 Pinggy 出站隧道：

### 3.5.1 一键脚本

```
scripts\serve_tunnel.bat
```

> 如果对方**不在同一 Wi-Fi**，请直接用 **3.6 的带密码版本**；3.5 这个直连版没有鉴权，只适合合成数据演示。

它会先检查 8000 是否在跑，然后用 Windows 自带的 `ssh` 连 Pinggy，终端会出现类似：

```
https://xxxx-xxx-xxx-xxx.run.pinggy-free.link
https://yyyy-xxx-xxx-xxx.free.pinggy.net
```

复制其中一个发给别人即可。

### 3.5.2 手动命令

```powershell
ssh -p 443 -o StrictHostKeyChecking=accept-new -o ServerAliveInterval=30 -R0:localhost:8000 a.pinggy.io
```

- 走 **443 端口出站**，不需要开任何入站端口、不需要管理员；
- 免费隧道 **60 分钟**，每次启动地址会变；
- 后端在 `127.0.0.1:8000` 就行（当前已经是 `0.0.0.0:8000`，也可以）。

### 3.5.3 已验证

我用同一条命令起隧道后，从外部访问：

```
https://...pinggy.../api/health  → 200 {"ok":true,"web":true}
https://...pinggy.../             → 200 PCI 术后用药管理助手
```

说明这条路径可用。验证完我已经把隧道关掉——**不要长期挂着一个无鉴权的公网医疗页面**。

### 3.5.4 安全警告

Pinggy 是**公网**地址：

- 任何拿到 URL 的人都能打开页面、调用 `/api/ocr`，消耗你的百炼额度；
- 3.5 直连版**没有登录/鉴权**；需要发到其他网络时用 3.6 的 Basic Auth 版本；
- 只放**合成数据**（`backend/samples/`），不要上传真实患者病历；
- 演示结束按 **Ctrl+C** 关闭隧道；
- 需要长期公网 + 登录，用 Tailscale、Cloudflare Access 或 Caddy Basic Auth，不要直接暴露。

### 3.5.5 其他无管理员方案

| 方案 | 命令 / 做法 | 备注 |
|---|---|---|
| Pinggy（已测） | `ssh -p 443 -R0:localhost:8000 a.pinggy.io` | 无需安装，60 分钟 |
| localtunnel | `npx --yes localtunnel --port 8000` | 需要 Node；访客可能要输 tunnel password |
| cpolar | 注册 cpolar → 下载客户端 → `cpolar http 8000` | 国内访问通常更稳，免费随机域名 |
| Cloudflare Tunnel | `winget install --id Cloudflare.cloudflared -e`，然后 `cloudflared tunnel --url http://127.0.0.1:8001 --no-autoupdate` | 本机已装；自动重连；配合 3.6 的密码代理 |
| Tailscale | 两台电脑装 Tailscale 登录同一账号 | 私有，不公开；安装通常需要管理员 |

> 这台机器的 `ssh` 是 Windows 自带的 OpenSSH 9.5，已经在。如果没有，去「设置 → 应用 → 可选功能 → 添加功能 → OpenSSH 客户端」安装。

## 3.6 不在同一 Wi-Fi：带密码的公网隧道（推荐）

如果对方在另一个网络（家里、另一个校区、手机流量），局域网 IP 一定打不开。用**出站隧道**把本机服务映射成公网 HTTPS，再加一层 Basic Auth，不需要同一 Wi-Fi、不需要开路由器端口。

### 3.6.1 一键启动

```text
scripts\serve_tunnel_auth.bat
```

脚本会：

1. 检查 8000 后端，没启动就后台启动；
2. 生成用户名 `doctor` + 随机密码（也可以提前设置 `$env:TUNNEL_PASSWORD` 固定密码）；
3. 启动 [`scripts/auth_proxy.py`](../scripts/auth_proxy.py)，监听 8001，给**所有请求**加 HTTP Basic Auth；
4. 如果装了 `cloudflared`，用 **Cloudflare Quick Tunnel**（自动重连，地址形如 `https://xxx.trycloudflare.com`）；没装则回退 Pinggy；
5. 终端打印公网地址、用户名、密码；关闭窗口/Ctrl+C 时停掉本次启动的代理和后端。

`cloudflared` 安装（本机已装）：

```powershell
winget install --id Cloudflare.cloudflared -e --accept-source-agreements --accept-package-agreements
```

### 3.6.2 拓扑

```text
其他电脑浏览器
   │  https://xxx.trycloudflare.com
   ▼
Cloudflare Quick Tunnel
   │  http://127.0.0.1:8001
   ▼
auth_proxy.py（Basic Auth）
   │  http://127.0.0.1:8000
   ▼
uvicorn + frontend/dist
```

- 浏览器第一次打开会弹登录框；用户名/密码就是脚本打印的两行。
- 登录后，页面里的 `/api/analyze`、`/api/ocr`、`/api/chat`（SSE）都会自动带同源凭据。
- 没有密码的请求返回 `401`，不会转发到 8000。

### 3.6.3 已验证

本次实际验证：

```text
https://...trycloudflare.com/api/health  无密码 → 401
https://...trycloudflare.com/api/health  带密码 → 200 {"ok":true,"web":true}
https://...trycloudflare.com/            带密码 → 200（新版页面）
POST /api/analyze                        带密码 → 200（可返回危急值）
```

### 3.6.4 注意事项

- Cloudflare Quick Tunnel **没有 uptime 保证**，地址在进程重启后会变；长期使用请用命名隧道 + Cloudflare Access，或 Tailscale 私有网络。
- 公网地址只发给授权的人；Basic Auth 不是强身份体系，真实患者数据仍建议用 Tailscale/ZeroTier 等私有网络。
- 免费 Pinggy 约 60 分钟会断；Cloudflare 没有 60 分钟硬限制，但校园网可能重置长连接，断了重新双击脚本即可。
- 如果校园网封了 443/QUIC，Cloudflare 会失败，脚本会回退 Pinggy（SSH 443）；两条都不行时用手机热点或 Tailscale。
- 不要直接把 8000 端口映射到路由器公网；本方案只暴露带密码的 8001 代理。

## 5. 方案 B：Vite 开发模式局域网

适合“还要继续改前端、要 HMR”的场景。`vite.config.ts` 已加：

```ts
server: {
  host: true,      // 绑定 0.0.0.0
  port: 5173,
  strictPort: true,
  proxy: { '/api': { target: 'http://127.0.0.1:8000', changeOrigin: true } },
}
```

步骤：

```powershell
# 后端仍然只绑本机即可，Vite 代理会转发
cd backend
.\venv\Scripts\python.exe -m uvicorn api:app --reload

# 前端
cd ..\frontend
npm.cmd run dev
```

其他电脑访问：

```
http://<本机IP>:5173
```

- 需要放行 **5173**；
- 改 `vite.config.ts` 后要重启 `npm run dev`；
- 后端可以继续 `127.0.0.1:8000`，因为代理运行在你的电脑上；
- 这是开发服务器，不是生产部署；演示更推荐方案 A。

## 6. 公网访问（谨慎）

### 6.1 Tailscale（推荐：私有，不公开）

适合“异地电脑也要看”，但只给自己人：

1. 两台电脑都装 Tailscale 并登录同一账号；
2. 本机执行 `tailscale ip -4` 拿到 `100.x.x.x`；
3. 本机按方案 A 启动（`--host 0.0.0.0`）；
4. 另一台电脑打开 `http://100.x.x.x:8000`。

只有同一个 tailnet 的设备能访问，不暴露给公网。医疗数据优先用这个。

### 6.2 Cloudflare Tunnel（公网 HTTPS，但无鉴权）

```powershell
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://127.0.0.1:8000
```

终端会打印一个 `https://xxxx.trycloudflare.com` 地址，发给别人即可打开。

**风险：**

- 这是**公网**地址，任何拿到 URL 的人都能访问；
- 应用没有登录/鉴权，别人可以调用 `/api/ocr` 消耗你的百炼额度；
- 页面上可能显示患者数据；公网演示请只用合成单（`backend/samples/`），不要用真实病历；
- 每次重启 cloudflared，URL 都会变。

需要公网 + 鉴权时，用 Cloudflare Access（给域名加登录）或 Caddy/Nginx 的 Basic Auth 反代到 8000；不要直接把 8000 暴露到路由器公网。

### 6.3 ngrok（同类）

```powershell
ngrok http 8000
```

同样是无鉴权公网地址，风险同上。

## 7. 安全清单（医疗数据）

- 应用**没有登录**；只在内网/私有网络用。
- 公网演示只用合成数据（`backend/samples/critical_lab_demo.png`、`ecg_demo.png`）。
- `.env` 里的 `DASHSCOPE_API_KEY` 只在后端，不要写进前端；`.env` 已在 `.gitignore`。
- `backend/samples/真实病历/` 已在 `.gitignore`，不要提交、不要放到公网演示。
- 局域网 HTTP 不加密；同一 Wi-Fi 下抓包可见。公网必须 HTTPS（Cloudflare Tunnel 自带）。
- 演示结束按 Ctrl+C 停服务；不要把 8000 长期开着。
- `/docs`（Swagger）也会暴露；公网时考虑关掉（`FastAPI(docs_url=None)`）或加反代鉴权。
- OCR 接口按次计费；没有限流，公网 URL 泄露可能被刷。

## 8. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 其他电脑“无法访问此网站” | 后端还是 `127.0.0.1`；必须 `--host 0.0.0.0`；检查防火墙 8000 |
| 其他电脑 ping 得通、网页打不开 | 防火墙入站规则没放行；网络被识别为“公用” |
| 页面能开，提交分析失败 | 看后端终端；单端口下 `/api/health` 是否 `ok:true`；OCR 是否 key 有效 |
| 页面空白 / assets 404 | `dist` 没构建或过期；`npm run build` 后重启后端 |
| `/api/health` 返回 `web:false` | `frontend/dist/index.html` 不存在 |
| 8000 被占用 | `netstat -ano \| findstr :8000`，停掉旧 uvicorn（Ctrl+C），或换 8002 并放行 |
| IP 变了 | DHCP 重新分配；`ipconfig` 重新看，或在路由器给本机固定 IP |
| 手机连不上 | 手机和电脑是否同一 Wi-Fi；访客网络常开 AP 隔离；改用手机热点 |
| Vite 5173 其他电脑打不开 | 改 `vite.config.ts` 后没重启 dev；防火墙 5173；`host: true` 是否生效 |
| 公网 URL 打开但 OCR 很慢/超时 | 每张 10–20 秒；公网延迟更高；不要一次传太多张 |
| 公网 HTTPS 页面里请求 HTTP | 不要混用；单端口同源或 tunnel 统一 HTTPS |

## 10. 后端改动说明

`backend/api.py` 末尾新增：

```python
DIST = Path(__file__).resolve().parent.parent / "frontend" / "dist"

if (DIST / "index.html").is_file():
    app.mount("/", StaticFiles(directory=str(DIST), html=True), name="web")
else:
    @app.get("/")
    def root():
        return {"msg": "前端未构建，先 npm run build 再重启"}
```

- 所有 `/api/*` 路由在 mount 之前注册，优先级更高；
- `/docs`、`/openapi.json` 也是先注册，不受影响；
- 没有 `dist` 时，`/` 返回提示 JSON，不会 500。

健康检查：

```python
@app.get("/api/health")
def health():
    return {"ok": True, "web": (DIST / "index.html").is_file()}
```
