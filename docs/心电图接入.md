# 心电图接入（第 4 步）

> 目标：让心电图报告也能回填「心率 / QTc / 基线 QTc / 窦性心律」，并触发 **CV-09（QTc）** 和 **CV-10（心率）** 两条危急值。
>
> 范围：`backend/ocr.py`（提示词/schema）、`backend/ocr_map.py`（ECG 规格 + 结论解析）、`frontend/src/App.vue`（心电图卡 3 个字段）。接口不变。

---

## 0. 效果

用合成心电图（[backend/samples/ecg_demo.png](backend/samples/ecg_demo.png)）实测：

```
心率(脉HR) = 35 次/分 ↓
QT/QTc间期 = 420/520 ms ↑
结论 = 窦性心动过缓；QTc 延长，请结合临床。
```

回填：

```
heart_rate    = 35
qtc           = 520      ← 取的是 520，不是 420
sinus_rhythm  = 是       ← 来自结论「窦性心动过缓」
critical      = ['CV-09', 'CV-10']
```

---

## 1. 为什么原来心电图 0 回填

原来的 `ocr.py` 提示词是「医疗**化验单**识别助手」，schema 只有 `items`，没有 `conclusion`。心电图报告的结果区是参数表（心率/PR/QRS/QT-QTc/电轴/SV1/RV5），模型会把它们当“检测项目”读出来；但：

- `ocr_map.py` 没有 `heart_rate / qtc` 规格；
- 报告最关键的「结论：窦性心律」在参数表之外，原 schema 根本没有地方放它；
- 所以 8 个参数全部进「未回填」，0 个字段。

---

## 2. 提示词/schema 改动（`backend/ocr.py`）

`SYSTEM_PROMPT` 从「化验单」扩展为「检查报告」，新增两个键：

```json
{
  "report_type": "lab / ecg / other（无法判断填 other）",
  "items": [
    {
      "item": "检测项目/参数中文名（照抄报告上的名字）",
      "value": "结果数值（原样字符串，如 3.8、阳性、<0.01、380/420）",
      "unit": "单位（如 mmol/L、g/L、×10^9/L、ms、次/分；无单位填空字符串）",
      "ref_range": "报告上印的参考范围（如 2.60-3.40；没印填空字符串）",
      "flag": "high / low / normal（依箭头或参考范围判断；无箭头且无参考范围时填 normal）"
    }
  ],
  "conclusion": "报告结论/诊断原文（心电图必填，如「窦性心律」「ST-T改变」；化验单没有则填空字符串）",
  "remark": "整张单的其他要点：带异常箭头但难以归类的项、'危急值'提示等；没有则填空字符串"
}
```

硬性要求新增两条：

```text
5. 心电图报告：把 心率、PR间期、QRS时限、QT/QTc间期、电轴、SV1、RV5、RV5+SV1 等参数照原样放进 items；
   把报告下方的「结论 / 诊断」原文放进 conclusion，不要改写、不要推断。QT/QTc 写成 380/420 时原样保留。
6. 化验单：conclusion 填空字符串。
```

> 关键：**结论只照抄，不让模型推断**。「窦性心律」必须来自报告原文，不能从心率/PR 等参数反推。

`api.py` 把 conclusion 传给映射：

```python
result.update(map_items(result.get("items", []), result.get("conclusion", "")))
```

## 3. 前端加心电图字段（`App.vue`）

「十二导联心电图」卡从 1 个字段变成 4 个：

```ts
{ name: '十二导联心电图', items: 'ST-T / 心律失常 / 心率 / QTc', fields: [
  { key: 'sinus_rhythm', label: '窦性心律', type: 'bool' },
  { key: 'heart_rate', label: '心率', type: 'number', unit: '次/分' },
  { key: 'qtc', label: 'QTc', type: 'number', unit: 'ms' },
  { key: 'qtc_baseline', label: '基线 QTc（既往）', type: 'number', unit: 'ms' },
]},
```

不用改 `buildPayload`：它遍历 `examCards`，自动把 `heart_rate / qtc / qtc_baseline` 收进请求体。`form` 初始化/重置也走同一循环。

`qtc_baseline` 是既往基线，单张当前心电图拿不到，必须手工填；CV-09 的「较基线增加 >60ms」靠它。

## 4. 映射规格（`ocr_map.py`）

### 4.1 心率

```python
{
    # 心率原始数值进心电图卡；CV-10 阈值 <40 或 >130 次/分
    "field": "heart_rate", "label": "心率", "kind": "number", "unit": "次/分",
    "card": "十二导联心电图",
    "aliases": ["心率", "心室率", "heartrate", "hr"],
    "exclude": ["变异性", "间期"],
    "expect_units": ["次/分", "bpm", "次/min"], "min": 20.0, "max": 300.0,
},
```

真实单的「心率(脉HR)」经 `_norm_name` 去掉括号后就是「心率」，能命中。

### 4.2 QTc：380/420 必须取 420

```python
{
    # QT/QTc 同时出现时（380/420）取最后一个数，避免把 QT 当 QTc
    "field": "qtc", "label": "QTc", "kind": "number", "unit": "ms",
    "card": "十二导联心电图",
    "aliases": ["qtc间期", "qtc", "qt/qtc间期", "qtqtc间期"],
    "exclude": [],
    "expect_units": ["ms"], "min": 100.0, "max": 800.0,
    "number_pick": "last",
},
```

`_last_num`：

```python
def _last_num(value):
    """取字符串里最后一个数：QT/QTc 的 380/420 要 QTc=420，不是 QT=380。"""
    s = unicodedata.normalize("NFKC", str(value or "")).replace(",", "")
    nums = _NUM_RE.findall(s)
    return float(nums[-1]) if nums else None
```

`map_items` 里先按 spec 选数，再算 flag：

```python
number = _num(value)
if spec.get("number_pick") == "last":
    number = _last_num(value)
flag = _flag_of(value, ref_range, raw.get("flag"), number)
```

`_flag_of` 新增可选 `number` 参数：

```python
def _flag_of(value, ref_range, given, number=None):
    v = number if number is not None else _num(value)
```

为什么必须这样：参考范围 `<440` 对 `420/520`，如果按第一个数 420 判，会算成 normal；按 520 判才是 high。QTc 的危急值 500 也必须用 520。

### 4.3 窦性心律：从结论派生

字段本身不匹配 items（心电图结论不在参数表里）：

```python
{
    "field": "sinus_rhythm", "label": "窦性心律", "kind": "bool", "unit": "",
    "card": "十二导联心电图",
    "aliases": [], "exclude": [],
},
```

结论解析：

```python
def _sinus_from_conclusion(text):
    """从心电图结论原文判断是否窦性心律；没有明确措辞就不填（返回 None）。"""
    t = _norm_name(text)
    if not t:
        return None
    if "非窦性" in t:
        return False
    if any(k in t for k in ("窦性心律", "窦性节律", "窦性心动过缓", "窦性心动过速", "窦性心律不齐")):
        return True
    if any(k in t for k in ("心房颤动", "房颤", "心房扑动", "房扑")):
        return False
    return None
```

在 `map_items` 的 items 循环结束后：

```python
if conclusion:
    sinus = _sinus_from_conclusion(conclusion)
    if sinus is not None:
        spec = SPEC_BY_FIELD["sinus_rhythm"]
        text = str(conclusion).strip()[:120]
        entry = accum.setdefault(spec["field"], {"spec": spec, "rows": []})
        entry["rows"].append({
            "source": {
                "item": "心电图结论", "value": text,
                "unit": "", "ref_range": "", "flag": "normal",
            },
            "number": None, "flag": "normal", "ref_range": "",
            "derived_value": sinus,
            "derived_from": "conclusion",
            "derived_item": "心电图结论",
            "derived_source_value": text,
        })
```

- 只有明确措辞才填；「窦性停搏」「交界性心律」这种不猜，留在未回填。
- 「非窦性心律」先判 false，避免被「窦性心律」子串误判成 true。
- 「心房颤动/房颤/房扑」判 false。

输出备注会写「由心电图结论「窦性心动过缓…」派生」，不是「数值派生」。

## 5. 危急值 CV-09 / CV-10

`rule_engine.py` 里早就有：

```python
CV-09：qtc > 500，或 qtc - qtc_baseline > 60
CV-10：heart_rate < 40 或 > 130
```

以前没有字段，永远不触发；现在表单有 `heart_rate / qtc / qtc_baseline`，提交就会命中。

例子：

| 输入 | 命中 |
|---|---|
| `heart_rate=35` | CV-10 |
| `qtc=520` | CV-09 |
| `qtc=480, qtc_baseline=400` | CV-09（差值 80ms） |
| `qtc=480`（无基线） | 不命中 |

## 8. 边界

1. **结论必须在图片里可读**：如果只拍参数表、没拍下方结论，`sinus_rhythm` 不会填；不猜。
2. **只认明确措辞**：窦性心律/节律/心动过缓/过速/不齐 → true；房颤/房扑/非窦性 → false；窦性停搏、交界性心律、室性心律不猜。
3. **PR / QRS / 电轴 / SV1 / RV5 还没字段**：目前只进「未回填」。要接需要表单字段，且没有对应的用药规则，优先级低。
4. **基线 QTc 手工填**：单张当前心电图没有既往基线。
5. **心电图与化验单可能来自不同患者**：多图合并仍靠「同一患者」警告；不要把不同患者的心电图和化验单一起上传。
6. **CV-03 校正钙仍未接**：需要 `calcium_corrected` 字段；这是 12 条危急值里唯一还缺的。
7. **窦缓与伊伐布雷定规则**：结论「窦性心动过缓」会置 `sinus_rhythm=true`（事实正确），但 `rule_engine` 的伊伐布雷定规则没有心率下限，40–59 次/分的窦缓 + β 阻滞剂禁忌/LVEF<40 时可能命中「可加用伊伐布雷定」。这是既有规则缺口，建议下一轮给该规则加 `heart_rate >= 60`（或 70）的下限；HR<40 已被 CV-10 压制，不会显示这条建议。
