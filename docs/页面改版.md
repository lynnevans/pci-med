## 1. 怎么切换 / 回退

- 使用新版：`frontend/src/main.ts` 里 `import AppV2 from './AppV2.vue'`（当前状态）。
- 回退旧版：把 `main.ts` 改成 `import App from './App.vue'`，并 `createApp(App)`。
- 全局样式在 `frontend/src/app.css`，由 `main.ts` 引入；新旧页面共用。

## 2. 全局规则（PDF 第 1 页）

### 2.1 必填三级

| 级别 | 实现 |
|---|---|
| 核心必填 | 年龄、性别、PCI 手术日期、出院诊断、病变支数、干预血管/方式；带红色 `*`，未填不能进入下一步 |
| 条件必填 | 勾选高血压 → 必须选分级；勾选房颤 → 必须选一种口服抗凝药 |
| 选填 | 体重、急诊 PCI、ASCVD 分层、出院方案、其他既往史、危急值补充、特殊用药情况等 |

校验函数：`validateStep(0/1/3)` + `validateAll()`。未通过时顶部红色 alert 列出所有问题，并跳到对应步骤。

> 年龄控件限制 30–100 岁；超出会提示“请复核”。

### 2.2 术语

页面标签使用中文全称（如“低密度脂蛋白胆固醇（LDL-C）”“高敏肌钙蛋白 T（hs-cTnT）”）。
关键缩写增加了 `title` 悬浮说明（`TERM_TIPS` / `termTip()`）：DAPT、hs-cTnT、室壁瘤、ARNI/ACEI/ARB、PPI、CCB、QTc、eGFR、LDL-C、HbA1c、BNP、INR。

### 2.3 评分项

按 PDF 要求删除了 CHA₂DS₂-VASc、HAS-BLED、PRECISE-DAPT 三个评分输入。
**影响**：后端规则里依赖这些评分的分支（如 HAS-BLED≥3 的高出血风险）会使用默认 0；这是按设计稿执行的取舍，不是 bug。需要恢复时可在第 2 步加回。

### 2.4 自动暂存 / 保存退出 / 覆盖确认

- 自动暂存：`watch(form, ..., {deep:true})` 500ms 防抖，写 `localStorage` 的 `pci-med-draft-v3`；打开页面自动恢复并提示“已为您恢复上次填写内容”。
- 保存并退出：每步右上角按钮，立即保存并弹窗提示可关闭页面。
- 覆盖确认：OCR 对话框新增「已填值」列和「冲突处理」列；对每个与表单已有值冲突的字段，医生可选「识别值 / 已填值」，选“已填值”的字段不回填。
- OCR 失败提示：“识别失败可以直接手动填写，不影响生成建议”。

## 4. 第 2 步：合并症与既往史

全部为开关，默认“无”；打开后展开子项：

- 高血压：分级（1/2/3/单纯收缩期）+“规范服药下血压仍 ≥140/90”
- 心房颤动
- 心力衰竭：HFrEF/HFmrEF/HFpEF
- 糖尿病：空腹血糖、糖化血红蛋白
- 高脂血症：当前降脂方案达标情况
- COPD / 哮喘（任一归入气道疾病）
- 肝功能异常：程度（轻度/重度）+ 异常项
- 慢性肾病：分期 + 肌酐清除率
- 既往心肌梗死：年份
- 既往脑梗死 / TIA：年份
- 消化道溃疡 / 出血史、痛风史、颅内出血史
- 其他合并症：文本框

后端映射：`hypertension_grade`、`bp_high`、`af`、`hf`、`diabetes`、`fbg_status`、`hba1c`、`dyslipidemia`、`need_start_lipid`/`statin_4_6w_not_goal`/`statin_ezetimibe_not_goal`/`statin_intolerant`、`asthma_copd`、`alt_ast_status`、`ckd`、`crcl`、`prior_mi_stroke`、`stroke_tia_history`、`ulcer_bleed_history`、`gout_history`、`ich_history`、`other_pmh`。

> 糖尿病里填的血糖/糖化与第 3 步检查卡是两处入口；检查卡有值时以后者为准，没有值时用糖尿病子项。

## 5. 第 3 步：辅助检查

卡片：血常规、尿常规、肝功能、肾功能、凝血功能、心肌酶谱、肌钙蛋白、电解质、血脂、空腹血糖和糖化、**心功能 BNP（新增）**、心电图、超声心动图、**危急值补充数值**。

- 血常规 / 肝功 / 肾功 / 心肌酶 / 肌钙蛋白 / 电解质 / 血糖糖化 / BNP 都同时提供**具体数值**和（部分）状态选择；血常规增加 24 小时前 Hb，血脂分开填写基线与本次 LDL-C。
- 心电图：ST-T 改变、心律失常、心率异常、QTc 延长、窦性心律、心率数值、QTc、基线 QTc。
- 超声：EF 数值、室壁瘤、室壁运动障碍、其他显著异常文本。
- 危急值补充：血钠、INR、纤维蛋白原、hs-cTnT、CO₂CP、基线肌酐、校正钙；全部选填。血钾/血小板/血红蛋白/心率/QTc 已在上面卡片填写，不重复。
- 卡片顶部不再显示“Hb / WBC / PLT”这类标注；每条卡片有简短提示。
- 上传：一次最多 **5 张**，JPG/PNG，逐张识别合并；多患者警告。

## 6. 第 4 步：用药（10 类）

按 PDF 的 10 类清单实现：

1. 抗血小板药物：阿司匹林、吲哚布芬、氯吡格雷、替格瑞洛
2. 口服抗凝药：利伐沙班、华法林
3. β 受体阻滞剂：美托洛尔、比索洛尔、卡维地洛
4. ARNI / ACEI / ARB：沙库巴曲缬沙坦、培哚普利、依那普利、贝那普利、福辛普利、缬沙坦、氯沙坦、厄贝沙坦、替米沙坦、坎地沙坦
5. 降脂：阿托伐他汀、瑞舒伐他汀、依折麦布、非诺贝特、依洛尤单抗、托莱西单抗、英克司兰、其他
6. 降糖：二甲双胍、阿卡波糖、达格列净、恩格列净、格列美脲、西格列汀、阿格列汀、甘精胰岛素、门冬胰岛素、德谷胰岛素、司美格鲁肽、其他
7. 利尿剂：呋塞米、螺内酯
8. PPI：雷贝拉唑、泮托拉唑、奥美拉唑
9. CCB：氨氯地平、硝苯地平、左氨氯地平、非洛地平、地尔硫䓬
10. 其他：单硝酸异山梨酯、厄贝沙坦氢氯噻嗪、尼可地尔、伊伐布雷定、维立西呱、托伐普坦、秋水仙碱、莫沙必利、门冬氨酸钾镁、铝镁加、血脂康、复方丹参滴丸、参松养心、心速宁、芪苈强心、诺迪康、尿毒清、百令、多烯磷脂酰胆碱、左甲状腺素、其他（填药名）

交互：

- 每类先开关“是否使用”；打开后勾选药物，每个药物分别填“出院时 / 现在”剂量；空白表示未使用。
- 抗血小板四种内置标准剂量提示（阿司匹林 100 qd、氯吡格雷 75 qd、替格瑞洛 90 bid、吲哚布芬 100 bid），“填标准量”一键写入“现在”。
- 顶部有已选药物摘要（含出院/现在剂量）。
- 自动对比：出院有剂量、现在为空/0 → 黄色提示“可能已停”；现在剂量小于出院 → 提示“剂量下降”。这只是提示，不替代医生判断。
- 合并房颤但未选抗凝药时，第 4 步显示红色条件必填提示，提交会被拦截。

后端映射：

- 抗血小板：`on_aspirin`/`on_clopidogrel`/`on_ticagrelor`/`on_indobufen` 及剂量；`on_antiplatelet`、`on_dapt`；`discharge_meds`。
- 抗凝：利伐沙班 → `on_noac` + `noac_type`；华法林 → `on_warfarin`。
- β → `on_beta_blocker` + `beta_blocker_type`。
- RAAS → `on_acei_arb` + `acei_arb_type`（ARNI/ACEI/ARB）。
- 利尿 → `on_diuretic` + `diuretic_type`；PPI → `ppi`；CCB → `on_ccb` + `ccb_type`。
- 他汀 → `on_statin`；二甲双胍 → `on_metformin`；硝酸酯 → `on_nitrate`；“其他”文本可识别胺碘酮/PDE5/NSAIDs。
- **当前用药标志只认“现在”剂量 >0**；仅出院时使用的药会写进 `discharge_meds`，不会当成当前用药。

## 7. 第 5 步：症状与用药行为

- 症状：胸痛、胸闷气短、晕厥、活动耐量下降；任一 → `red_flag`，胸痛额外 `chest_pain`（CV-11）。
- 出血：严重四项（呕血、黑便、近期致命出血史、颅内出血史）红色置顶；尿血、淤青、牙龈出血在后。
  - 呕血/黑便/尿血 → `red_flag`；近期致命 → `recent_fatal_bleed`；颅内 → `ich_history`；淤青/牙龈 → `mild_bleed`。
- 临时用药：文本框；关键词识别鱼油/纳豆/活血 → `blood_activating`；镇痛/布洛芬 → `need_analgesic`、`on_nsaid_steroid`。
- 用药依从性：勾选药物 + 停用天数 → `self_stop_days`；勾选抗血小板 → `want_stop_antiplatelet`。
- 拟行增强 CT/造影 → `enhance_ct`。
- 拟行其他手术：名称 + 预计日期 → `planned_surgery`。
- 折叠“其他”：药物相关表现（干咳/水肿/心动过缓/心率快/抗缺血不佳）→ 对应字段；下转信息 → `referral_plan_confirmed`、`recent_symptom_after_referral`（保留旧规则输入）。

## 9. 结果页（V1.0 八部分结构化报告）

结果页由 `frontend/src/components/AnalysisReport.vue` 按固定顺序渲染：

1. 患者概要：信息卡、数据完整度、120 字以内临床画像与综合风险。
2. 合并症与既往史：仅列已报告项目，显示控制情况、用药关联与出处。
3. 检查指标评估：危急值 → 需关注异常（轻/中/重）→ 正常确认（默认折叠）→ 信息缺口。
4. 当前用药评估：二级预防完整性 → 药病相互影响 → 加药/换药/停药/调量清单。
5. 症状与用药行为影响评估。
6. 综合结论与处理优先级：一级立即、二级尽快门诊、三级长期管理，编号连续并引用前文条目。
7. 随访与转诊建议：按命中项目生成复查表与转诊指征。
8. 依据与说明：实际引用指南、术语对照和固定免责声明。

后端 `report_builder.py` 输出 `summary、comorbidity、exam_critical、exam_attention、exam_normal、exam_gap、medication_gap、drug_disease、adjust_plan、symptom_behavior、action_plan、followup、references` 十三组字段。正式建议统一包含结论、证据、影响、动作、时限和依据；`/api/analyze` 同时保留原 `critical / redlines / advices` 字段以兼容旧调用方。

页脚保留打印 / 导出 PDF（浏览器打印对话框另存为 PDF）、返回核对页、重新填写；打印样式会展开正常确认等折叠内容。

## 11. 与 PDF 的差异 / 已知边界

1. **评分类字段删除**：CHA₂DS₂-VASc、HAS-BLED、PRECISE-DAPT 不再录入，相关后端规则使用默认 0；高风险人群识别可能变钝。
2. **部分检查没有对应用药规则**：`urine_protein`、`tc/tg/hdl`、`lipid_abnormal`、`st_t/arrhythmia/hr_abnormal/qtc_prolonged`、`echo_other`、`bnp` 等会保存，但不触发独立用药规则；原始 ALT/AST、CK、肌钙蛋白等可用于报告证据。
3. **“指南原文段落”未展开**：报告把来源编号映射为项目内指南名称，并保留规则 ID；不伪造指南原文、年份或未核对的条目号。
4. **部分分档依赖人工状态**：ALT/AST 尚未录入相对正常上限倍数，报告会采用人工轻/中/重状态并同时列出信息缺口；本院参考范围也不会由系统虚构。
5. **OCR 的 LDL-C 仍回填基线值**：本次 LDL-C 需人工核对并填写，避免把基线值误作当前达标判断。
6. **糖尿病血糖/糖化与检查卡重复入口**：检查卡有值时优先；没有值时用糖尿病子项。
7. **当前用药只认“现在”剂量**：出院时使用、现在为空的药，不会被当成当前用药；报告会把缺少当前剂量的已选药列入信息缺口。
8. **多图只靠人工确认同一患者**：没有患者身份校验；不同患者一起上传会合并成一份表单。
9. **`?step=` 是开发入口**：不参与业务，可随时删除。
10. **旧 App.vue 保留**：回退方式见第 1 节；旧页不含新版结构化报告。
11. **自动暂存含患者数据**：草稿写在浏览器 `localStorage`（键 `pci-med-draft-v3`），未加密；共用电脑请在结果页点「重新填写」清除，或手动清浏览器站点数据。
12. **正常确认不等于完整体检**：仅对已录入且未触发异常阈值的指标作正面确认；未录入项目单独列为信息缺口，不自动视为正常。
