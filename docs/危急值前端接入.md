# 危急值前端接入（第 1 步）

> 目标：让 `rule_engine.py` 已经算好的 12 条危急值（`critical`）在页面上真正显示出来，并补上 9 个原始数值输入框，使危急值可以被手工触发、验收。
>
> 范围：**只改 `frontend/src/App.vue` 一个文件**，不改后端、不改接口、不改依赖。
>
> 适用：`pci-med` 项目（Vue 3 + TypeScript + Element Plus + Vite），后端 FastAPI。

---

## 0. 先理解：为什么非改不可

后端 `backend/rule_engine.py` 的 `match()` 早就返回了 `critical`：

```python
return {
    "tags": tags,
    "critical": criticals,   # ← 12 条危急值，最高优先级
    "redlines": [...],
    "advices": [...],
}
```

但前端 `App.vue` 的结果类型里没有这个字段：

```ts
interface AnalyzeResult {
  tags: Record<string, boolean>
  redlines: Redline[]
  advices: Advice[]
  disclaimer?: string
}
```

TypeScript 不会因为多返回一个字段而报错，于是 `critical` 被**静默丢掉**。更严重的是：

```python
# 危急值 / 红线命中时，不输出常规建议
hit_rules = [] if (criticals or hit_red) else [r for r in RULES if r["cond"](ctx)]
```

一旦命中危急值，`advices` 就是空数组，而原来的页面在“没有红线”时会显示：

> 未命中任何规则，请核对录入信息

也就是说：**血钾 6.5 这种要命的数值，页面会告诉你“没命中规则”**。这是本次要先修它的根本原因。

第二个原因：表单里原来没有 `hb / plt / potassium / inr` 这些**原始数值**输入，只有“血钾 正常/高/低”这种状态。危急值的判定全部依赖数值阈值（例如 `potassium > 6.0`），没有数值入口，危急值永远不可能被触发，也就没法验收。

## 1. 数据流（改完后）

```

        │
        ▼

        （不再显示“未命中任何规则”）
```

## 3. 逐处修改（共 8 处）

> 行号是本文写作时的行号；你从上往下改，行号会往后偏移，**按“搜索原文”定位最稳**。

### 3.1 给结果类型补 `critical`

**位置**：`App.vue` 顶部，`interface AnalyzeResult` 之前。

**作用**：告诉 TypeScript “接口返回里可能有一个 `critical` 数组”。它只是类型声明，不产生运行时代码；没有它，模板里写 `result.critical` 会报类型错误（或者被当成 `any`）。

**原文**：

```ts
interface AnalyzeResult {
  tags: Record<string, boolean>
  redlines: Redline[]
  advices: Advice[]
  disclaimer?: string
}
```

**改为**：

```ts
interface CriticalValue {
  id: string
  name: string
  action: string
}

interface AnalyzeResult {
  tags: Record<string, boolean>
  critical?: CriticalValue[]
  redlines: Redline[]
  advices: Advice[]
  disclaimer?: string
}
```

> **小白解释**：`critical?:` 里的问号表示“这个字段可以不存在”。这样即使后端是旧版本、没有返回 `critical`，前端也不会崩，只是不显示危急值卡片。

### 3.2 新增「危急值数值」卡片

**位置**：`examCards` 数组末尾（现在是「超声心动图」之后、数组的 `]` 之前）。

**作用**：给 9 个原始数值提供输入框。它们会**自动**完成三件事，不需要再写额外代码：

1. 自动渲染成一张检查卡片（因为页面是 `v-for="c in examCards"` 数据驱动）；
2. 自动初始化 `form.hb = null` 等（初始化循环遍历 `examCards`）；
3. 自动进入请求体（`buildPayload` 遍历 `examCards`，把所有 `type === 'number'` 的字段塞进 payload）。

**原文（数组结尾）**：

```ts
  { name: '十二导联心电图', items: 'ST-T / 心律失常', fields: [
    { key: 'sinus_rhythm', label: '窦性心律', type: 'bool' },
  ]},
  { name: '超声心动图', items: 'EF / 室壁瘤 / 室壁运动', fields: [
    { key: 'lvef', label: 'LVEF', type: 'number', unit: '%' },
    { key: 'wall_abnormality', label: '室壁瘤/室壁运动异常', type: 'bool' },
  ]},
]
```

**改为**：

```ts
  { name: '十二导联心电图', items: 'ST-T / 心律失常', fields: [
    { key: 'sinus_rhythm', label: '窦性心律', type: 'bool' },
  ]},
  { name: '超声心动图', items: 'EF / 室壁瘤 / 室壁运动', fields: [
    { key: 'lvef', label: 'LVEF', type: 'number', unit: '%' },
    { key: 'wall_abnormality', label: '室壁瘤/室壁运动异常', type: 'bool' },
  ]},
  // 危急值数值：rule_engine.CRITICAL_VALUES 用原始数值判定；选填，不填不影响用药规则
  { name: '危急值数值', items: '仅用于危急值阈值判定（选填）', fields: [
    { key: 'hb', label: '血红蛋白 Hb', type: 'number', unit: 'g/L' },
    { key: 'plt', label: '血小板 PLT', type: 'number', unit: '×10^9/L' },
    { key: 'potassium', label: '血钾 K⁺', type: 'number', unit: 'mmol/L' },
    { key: 'sodium', label: '血钠 Na⁺', type: 'number', unit: 'mmol/L' },
    { key: 'inr', label: 'INR', type: 'number', unit: '' },
    { key: 'fibrinogen', label: '纤维蛋白原 Fib', type: 'number', unit: 'g/L' },
    { key: 'hs_ctnt', label: '高敏肌钙蛋白 T hs-cTnT', type: 'number', unit: 'ng/mL' },
    { key: 'co2cp', label: '二氧化碳结合率 CO₂CP', type: 'number', unit: 'mmol/L' },
    { key: 'baseline_scr', label: '基线肌酐（48–72h 前）', type: 'number', unit: 'μmol/L' },
  ]},
]
```

**这 9 个字段分别能触发什么**：

| 字段 | 单位 | 对应危急值 | 阈值 |
|---|---|---|---|
| `potassium` | mmol/L | CV-01 血钾 | <3.0 或 >6.0 |
| `sodium` | mmol/L | CV-02 血钠 | <120 或 >160 |
| `hb` | g/L | CV-04 血红蛋白 | <70（或 24h 降 >20） |
| `plt` | ×10^9/L | CV-05 血小板 | <20 |
| `inr` | 无 | CV-07 INR（需华法林） | >4.0 |
| `fibrinogen` | g/L | CV-08 纤维蛋白原 | <1.0 |
| `hs_ctnt` | ng/mL | CV-11 肌钙蛋白+胸痛 | >0.07 且胸痛 |
| `co2cp` | mmol/L | CV-12 二氧化碳结合率 | <15 |
| `baseline_scr` | μmol/L | CV-06 AKI | 与当前 Scr 比，升 ≥26.5 或 ≥1.5× |

> **小白解释**：为什么不用原来的「血钾 正常/高/低」？因为状态只有三档，无法区分 6.1 和 6.9，而危急值要的是精确阈值。数值卡和状态卡是两套输入：数值卡负责“报警”，状态卡负责“用药规则”。手工录入时如果数值异常，请顺手把上面状态也改掉；等第 2 步 OCR 接入后，两者会一起自动填。

### 3.3 让「华法林」置 `on_warfarin`

**位置**：`buildPayload()` 里 `for (const g of medSingleGroups)` 循环。

**作用**：CV-07 的条件是 `on_warfarin and inr > 4.0`。原来选“华法林”只会被当成 NOAC（`on_noac = true`、`noac_type = '华法林'`），`on_warfarin` 永远是空，所以 INR 再高也不会触发 CV-07。

**原文**：

```ts
  for (const g of medSingleGroups) {
    const v = form[g.key]
    if (!v || v === '未使用') continue
    const m = singleMap[g.key]
    if (g.key === 'ppi') p['ppi'] = v
    else {
      p[m.on] = true
      p[m.type] = g.key === 'ccb' ? CCB_TYPE[v] : v
    }
  }
```

**改为**：

```ts
  for (const g of medSingleGroups) {
    const v = form[g.key]
    if (!v || v === '未使用') continue
    const m = singleMap[g.key]
    if (g.key === 'ppi') p['ppi'] = v
    else if (g.key === 'noac' && v === '华法林') {
      // 华法林不是 NOAC：只置 on_warfarin（危急值 CV-07 依赖），不置 on_noac
      p['on_warfarin'] = true
    } else {
      p[m.on] = true
      p[m.type] = g.key === 'ccb' ? CCB_TYPE[v] : v
    }
  }
```

> **小白解释**：这一段是“表单选项 → 后端字段”的翻译。选「华法林」时，现在翻译成 `on_warfarin: true`；选利伐沙班/达比加群时仍然走原来的 NOAC 分支。这样不会影响原有的 NOAC 肾功能减量规则（`_cm07` 对华法林本来就返回 False）。

### 3.4 让「胸痛」置 `chest_pain`

**位置**：`buildPayload()` 的「界面 5：症状/出血翻译」开头。

**作用**：CV-11 的条件是 `chest_pain and hs_ctnt > 0.07`。原来勾「胸痛」只置了 `red_flag = true`，`chest_pain` 永远是空。

**原文**：

```ts
  // ---------- 界面 5：症状/出血翻译 + 直接字段 ----------
  if ((form.symptoms || []).length) p['red_flag'] = true
```

**改为**：

```ts
  // ---------- 界面 5：症状/出血翻译 + 直接字段 ----------
  if ((form.symptoms || []).length) p['red_flag'] = true
  if ((form.symptoms || []).includes('胸痛')) p['chest_pain'] = true   // 危急值 CV-11 需要
```

> **小白解释**：`form.symptoms` 是数组（多选），`includes('胸痛')` 判断里面有没有“胸痛”这一项。原来只判断“数组非空”，所以勾“胸闷气短”也会置 `red_flag`，但不会置 `chest_pain`。

### 3.5 结果页渲染危急值卡片

**位置**：结果页 `<!-- ===== 分析结果 ===== -->` 里，红线块 `<div v-if="result.redlines ...">` 之前。

**作用**：把 `critical` 数组渲染成红色卡片，显示编号、名称、处置动作。`v-for` 会为每一条危急值生成一张卡；同一次可以命中多条（比如同时 K 6.5 + Hb 65）。

**插入位置（原文是这一行，在它前面插入）**：

```html
        <div v-if="result.redlines && result.redlines.length" class="redline-list">
```

**插入内容**：

```html
        <!-- 危急值：最高优先级；命中时后端已不再输出常规建议 -->
        <div v-if="result.critical && result.critical.length" class="critical-list">
          <div v-for="c in result.critical" :key="c.id" class="critical-item">
            <div class="critical-head">
              <el-icon :size="22" color="#fff"><WarningFilled /></el-icon>
              <span class="critical-title">【危急值 {{ c.id }}】{{ c.name }}</span>
            </div>
            <p class="critical-action">{{ c.action }}</p>
          </div>
        </div>

        <div v-if="result.redlines && result.redlines.length" class="redline-list">
```

> **小白解释**：`v-if="result.critical && result.critical.length"` 的意思是“先把 `critical` 取出来，存在且长度大于 0 才渲染”。`v-for` 是循环，`:key="c.id"` 给每条一个唯一标识，Vue 更新列表时不会错位。

### 3.6 修掉“未命中规则”的错误空态

**位置**：结果页红线块后面的 `<div v-else class="advice-list">`。

**作用**：`v-else` 只跟**紧挨着的** `v-if`（红线块）配对。危急值命中、红线没命中时，红线块不渲染，`v-else` 就会渲染“未命中任何规则”的空态——和上面的红色危急值卡自相矛盾。

**原文**：

```html
        <div v-else class="advice-list">
```

**改为**：

```html
        <div v-else-if="!result.critical || result.critical.length === 0" class="advice-list">
```

> **小白解释**：`v-else-if` 是“否则如果”。现在只有当「没有红线」**并且**「没有危急值」时，才显示常规建议/空态。如果命中了危急值，常规建议区整个不显示，页面只剩红色的危急值卡片，不会被空态误导。
>
> 注意：`v-else-if` 必须紧跟在红线块的 `v-if` 后面，中间不能插入别的元素。第 3.5 步的危急值块插在红线块**前面**，所以不影响这个配对关系。

### 3.8 把「危急值数值」卡改成整行宽卡（布局）

**位置**：`examCards` 的渲染循环 + `<style>` 里的 `.ctrl-sm`。

**问题**：这张卡只有 9 个数字框，却被放在和其他小卡一样的 280px 单列里，标签长、输入框窄，最后一排还空一大片，视觉上很别扭。

**第 1 处：给卡片加一个只属于它的 class**。原文：

```html
            <div v-for="c in examCards" :key="c.name" class="exam-card">
```

改为：

```html
            <div v-for="c in examCards" :key="c.name" :class="['exam-card', { 'exam-card-wide': c.name === '危急值数值' }]">
```

> `:class` 可以传数组 + 对象：数组里是固定 class，对象里 `键: 条件` 表示条件为真才加这个 class。这样只有“危急值数值”这张卡会拿到 `exam-card-wide`，其他卡完全不受影响。

**第 2 处：加宽卡样式**。在 `.ctrl-sm { width: 150px; }` 之后追加：

```css
/* 危急值数值：整行宽卡 + 两列；标签在上、输入框占满列宽，避免 9 个数字框挤在 280px 单列里 */
.exam-card-wide { grid-column: 1 / -1; }
.exam-card-wide .exam-body { display: grid; grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 14px 26px; }
.exam-card-wide .exam-field { flex-direction: column; align-items: stretch; gap: 6px; }
.exam-card-wide .ctrl-sm { width: 100%; }
```

> `grid-column: 1 / -1` 表示“从第一列跨到最后一列”，也就是占满整行。卡片内部改成两列网格；每个字段改成“标签在上、输入框在下”，输入框占满整列（约 300–400px），比原来 150px 宽一倍，也不会因为长标签把输入框挤窄。

**第 3 处：手机端改回单列**。在原有 `@media (max-width: 640px)` 里追加两行：

```css
  .exam-card-wide .exam-body { grid-template-columns: 1fr; }
  .exam-card-wide .ctrl-sm { width: 100%; }
```

> 手机屏幕放不下两列 380px，所以强制一列、输入框占满，避免横向溢出。

### 4.3 如果第 1 条没出现红卡

按顺序排查：

1. 浏览器 Console 有没有报错？（F12 → Console）
2. Network 里 `POST /api/analyze` 的 **Response** 有没有 `critical`？没有 → 后端问题，回到 2.1/2.2。
3. 有 `critical` 但页面没显示 → 3.5/3.7 没改对，或 `AnalyzeResult` 没改（3.1）。
4. 页面显示“未命中任何规则” → 3.6 没改。
5. 数值框填了但 Network 的 Request 里没有 `potassium` → 3.2 的卡没放进 `examCards`，或放到了数组外面。

## 6. 已知边界（这一版故意没做）

1. **数值卡和状态卡是两套输入**：只填数值不会自动改「血钾 正常/高/低」等状态。危急值命中时后端会压制常规建议，所以危急值演示不受影响；但“不构成危急值、只是轻度异常”的情况，需要手工把状态也改掉。
2. **CV-03 校正钙仍未接**：需要 `calcium_corrected` 字段。CV-09（QTc）/CV-10（心率）已在心电图卡接入，见 [心电图接入.md](心电图接入.md)。
3. **OCR 填数值已在第 2 步补上**：`ocr_map.py` 现在会把「钾 6.5」同时填成 `potassium=6.5` 和 `potassium_status=高`，详见 [OCR危急值映射.md](OCR危急值映射.md)。
4. **`hb` 没有参与人群标签**：`compute_tags` 用的是 `hb_low`（是否降低），不是 `hb` 数值。填了 Hb 65 会触发 CV-04，但不会让 `tag_br` 变化；这是现有规则的设计，不是本次改动引入的。

## 7. 第 2 步（已完成）

## 附：后端契约

`POST /api/analyze` 的响应新增字段（本次不改，只依赖）：

```json
{
  "tags": { "tag_br": false, "tag_ir": false, "tag_el": false },
  "critical": [
    { "id": "CV-01", "name": "血钾危急值", "action": "危急值：血钾 <3.0 或 >6.0 mmol/L……" }
  ],
  "redlines": [],
  "advices": [],
  "disclaimer": "本结果仅供基层医生辅助参考，不构成医疗决策，最终用药以专科医师判断为准。"
}
```

`critical` 为空数组时前端不渲染红卡；`critical` 非空时后端保证 `advices` 为空（危急值优先）。
