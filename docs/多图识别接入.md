# 多图识别接入（第 3 步）

> 目标：一次选择多张化验单，逐张识别后合并成一份表单；同一字段多张单子数值不一致时**不自动选**，标「多图冲突」让医生只勾一条。
>
> 范围：前端为主（`ocr.ts`、`OcrDialog.vue`），后端只补真实单里发现的凝血别名；`/api/ocr` 接口不变。

---

## 0. 现在能做什么

- 「选择图片（可多选）」一次最多 5 张，按顺序逐张识别，缩略图显示每张状态（等待/识别中/完成/失败）。
- 进度条 +「第 2 / 5 张 · 12s」，可「停止」；已完成的保留，可「继续识别剩余」。
- 单张失败不影响其他张；失败列表带文件名和原因，可「重试失败」。
- 与表单已有值冲突时，结果表出现「已填值」和「冲突处理」列，医生可按字段选择保留「识别值 / 已填值」；选“已填值”的字段不回填。
- 合并规则：
  - 同字段同值 → 合并成一行，来源显示「图1、图3」；
  - 同字段不同值 → 保留两行，都标「多图冲突」，默认只勾第一行；如果两条都勾，点「确认回填」会被拦下。
- 多图会合并成同一份患者表单，界面有醒目警告：**仅限同一位患者**。
- 长条化验单不再被压成 376px 宽：压缩策略从「长边 2000px」改为「400 万像素 + 高 5000px」。

---

## 1. 为什么是「前端逐张调」，不是「后端批量」

没有新增 `/api/ocr/batch`，而是前端循环调用原来的 `/api/ocr`：

| 方案 | 问题 |
|---|---|
| 一次请求塞 8 张 base64 | 请求体巨大；中途一张失败全部重来；没有逐张进度；单次请求可能 2–5 分钟，网关容易超时 |
| 后端批量 + 一次性返回 | 同样没有进度；失败隔离差；前端无法在识别到一半时停止 |
| **前端逐张 + 合并已映射字段** | 每张独立成功/失败；可停止、可续跑、可单张重试；请求体小；映射仍然 100% 在后端 |

合并的只是**已经映射好的字段**（`field/value/kind/sources`），不是重新做医学判断。字段映射仍然只在 `backend/ocr_map.py`。

---

## 2. 合并规则（`mergeOcrResults`）

| 情况 | 处理 |
|---|---|
| 同字段、同值 | 合并为一行；`imageIndexes` 追加图片编号；`sources` 去重合并；`note` 去重合并 |
| 同字段、不同值 | 两行都保留；`conflict=true`；备注「与其他图片的「血钾」结果不一致，请只勾选一条」 |
| warnings 相同文本 | 合并为一条，前面标「图1、图3：」 |
| unmatched 相同项目/值/原因 | 合并为一条，保留 `imageIndexes` |
| disclaimer | 取第一张非空的 |
| 识别项次数 | 各图 `items` 数量相加（含重复，只作展示） |

**默认选中策略**：`selectDefaults()` 只勾每个字段的第一行。这样冲突时不会默认两条都回填；医生要换另一张的值，需要先勾第二行、再取消第一行。

**应用前校验**：`confirmApply()` 检查选中行是否有重复 `field`；有则报错「「血钾」勾选了多条，请只保留一条（多图冲突）」，不写表单。

## 3. 代码改动

### 3.1 `frontend/src/ocr.ts`：合并函数

新增类型：

```ts
export interface OcrBatchImageResult {
  index: number
  name: string
  result: OcrApiResult
}

export interface MergedOcrField extends OcrMappedField {
  imageIndexes: number[]
  imageNames: string[]
  conflict: boolean
}

export interface MergedOcrUnmatched extends OcrSourceItem {
  imageIndexes: number[]
}

export interface MergedOcrResult {
  fields: MergedOcrField[]
  unmatched: MergedOcrUnmatched[]
  warnings: string[]
  itemCount: number
  disclaimer: string
}
```

核心函数（完整）：

```ts
export function mergeOcrResults(results: OcrBatchImageResult[]): MergedOcrResult {
  const rows: MergedOcrField[] = []
  const byField = new Map<string, MergedOcrField[]>()
  const unmatchedMap = new Map<string, MergedOcrUnmatched>()
  const warningMap = new Map<string, number[]>()
  let itemCount = 0
  let disclaimer = ''

  for (const { index, name, result } of results) {
    itemCount += result.items?.length ?? 0
    if (!disclaimer && result.disclaimer) disclaimer = result.disclaimer

    if (result.remark) {
      const text = `模型备注：${result.remark}`
      const indexes = warningMap.get(text) ?? []
      if (!indexes.includes(index)) indexes.push(index)
      warningMap.set(text, indexes)
    }

    for (const warning of result.warnings ?? []) {
      const indexes = warningMap.get(warning) ?? []
      if (!indexes.includes(index)) indexes.push(index)
      warningMap.set(warning, indexes)
    }

    for (const item of result.unmatched ?? []) {
      const key = `${item.item}|${item.value}|${item.unit}|${item.reason || ''}`
      const found = unmatchedMap.get(key)
      if (found) {
        if (!found.imageIndexes.includes(index)) found.imageIndexes.push(index)
      } else {
        unmatchedMap.set(key, { ...item, imageIndexes: [index] })
      }
    }

    for (const field of result.fields ?? []) {
      const existing = byField.get(field.field) ?? []
      let row = existing.find((candidate) => sameValue(candidate.value, field.value))

      if (!row) {
        row = {
          ...field,
          imageIndexes: [],
          imageNames: [],
          conflict: existing.length > 0,
          note: field.note,
        }
        if (existing.length > 0) {
          const message = `与其他图片的「${field.label}」结果不一致，请只勾选一条`
          row.note = appendNote(row.note, message)
          for (const other of existing) {
            other.conflict = true
            other.note = appendNote(other.note, message)
          }
        }
        rows.push(row)
        byField.set(field.field, [...existing, row])
      }

      if (!row.imageIndexes.includes(index)) row.imageIndexes.push(index)
      if (!row.imageNames.includes(name)) row.imageNames.push(name)
      for (const source of field.sources ?? []) {
        if (!row.sources.some((candidate) => sameSource(candidate, source))) {
          row.sources.push(source)
        }
      }
      if (field.note) row.note = appendNote(row.note, field.note)
    }
  }

  // 同一字段的多行放在一起（冲突行相邻），其余按首次出现顺序
  const firstSeen = new Map<string, number>()
  rows.forEach((row, i) => {
    if (!firstSeen.has(row.field)) firstSeen.set(row.field, i)
  })
  rows.sort(
    (a, b) =>
      (firstSeen.get(a.field) ?? 0) - (firstSeen.get(b.field) ?? 0) ||
      (a.imageIndexes[0] ?? 0) - (b.imageIndexes[0] ?? 0),
  )

  return {
    fields: rows,
    unmatched: [...unmatchedMap.values()],
    warnings: [...warningMap.entries()].map(
      ([text, indexes]) => `${indexes.map((i) => `图${i + 1}`).join('、')}：${text}`,
    ),
    itemCount,
    disclaimer,
  }
}
```

辅助函数：

```ts
function sameValue(a: unknown, b: unknown): boolean {
  if (typeof a === 'boolean' || typeof b === 'boolean') return Boolean(a) === Boolean(b)
  return String(a) === String(b)
}

function sameSource(a: OcrSourceItem, b: OcrSourceItem): boolean {
  return (
    a.item === b.item &&
    a.value === b.value &&
    a.unit === b.unit &&
    a.ref_range === b.ref_range &&
    (a.flag || '') === (b.flag || '')
  )
}

function appendNote(base: string | undefined, extra: string | undefined): string {
  const parts: string[] = []
  for (const raw of `${base || ''}；${extra || ''}`.split('；')) {
    const text = raw.trim()
    if (text && !parts.includes(text)) parts.push(text)
  }
  return parts.join('；')
}
```

### 3.2 长图压缩策略

**原逻辑**（会毁掉长条单）：

```ts
const MAX_EDGE = 2000
const scale = Math.min(1, MAX_EDGE / Math.max(width, height))
```

一张 1224×6502 的单子会被压成 **376×2000**，字高只剩几个像素。

**新逻辑**：

```ts
const MAX_PIXELS = 4_000_000
const MAX_HEIGHT = 5000

// 长条化验单按长边压到 2000px 会只剩 376px 宽，文字直接糊掉。
// 改成「4MP 总像素 + 5000px 高」双上限，优先保住宽度。
const scale = Math.min(1, Math.sqrt(MAX_PIXELS / (width * height)), MAX_HEIGHT / height)
```

同一条 1224×6502 现在压到约 **868×4611**（4MP），宽度是原来的 2.3 倍。

> 如果真实单还是看不清，下一步要做「纵向切块」：把一张长单切成 3–5 张 1224×1600 的块（带 120px 重叠），每块单独 OCR，再用同一套合并逻辑去掉重叠。这是比继续加像素更稳的办法。

### 3.3 `frontend/src/components/OcrDialog.vue`：批量状态机

批量的核心状态：

```ts
type BatchStatus = 'pending' | 'running' | 'done' | 'error'

interface BatchItem {
  id: number
  name: string
  prepared: PreparedImage
  status: BatchStatus
  result?: OcrApiResult
  error?: string
}

const items = ref<BatchItem[]>([])
const activeIndex = ref(-1)
const busy = ref(false)
const preparing = ref(false)
```

逐张识别（关键：一张失败继续下一张；停止时当前张退回 pending）：

```ts
async function runAll(): Promise<void> {
  if (busy.value || preparing.value) return
  const queue = items.value.filter((it) => it.status !== 'done')
  if (!queue.length) return

  busy.value = true
  errorMsg.value = ''
  const currentController = new AbortController()
  controller = currentController
  let aborted = false

  for (const item of queue) {
    if (!props.modelValue) { aborted = true; break }
    item.status = 'running'
    item.error = ''
    activeIndex.value = items.value.indexOf(item)
    elapsed.value = 0

    try {
      const data = await requestOcr(item.prepared, props.cardHint ?? '', currentController.signal)
      if (data.error) {
        item.status = 'error'
        item.error = data.error
      } else {
        item.result = data
        item.status = 'done'
      }
    } catch (err) {
      if (err instanceof DOMException && err.name === 'AbortError') {
        item.status = 'pending'
        aborted = true
        break
      }
      item.status = 'error'
      item.error = err instanceof Error ? err.message : String(err)
    }
  }

  busy.value = false
  if (controller === currentController) controller = null
  activeIndex.value = -1
  if (!props.modelValue) return
  if (aborted) errorMsg.value = '已停止识别，可点「继续识别」处理剩余图片'
  else if (failedCount.value) errorMsg.value = `${failedCount.value} 张图片识别失败，可重试`
  if (doneCount.value) await selectDefaults()
}
```

默认选中第一条 + 应用前拦重复：

```ts
async function selectDefaults(): Promise<void> {
  await nextTick()
  const table = tableRef.value
  if (!table) return
  table.clearSelection()
  const seen = new Set<string>()
  for (const row of fields.value) {
    if (seen.has(row.field)) continue
    seen.add(row.field)
    table.toggleRowSelection(row, true)
  }
}

function confirmApply(): void {
  const seen = new Set<string>()
  for (const row of selected.value) {
    if (seen.has(row.field)) {
      ElMessage.error(`「${row.label}」勾选了多条，请只保留一条（多图冲突）`)
      return
    }
    seen.add(row.field)
  }
  // ...构建 patch，emit('apply')
}
```

- 单张保持原来的大预览；多张显示缩略图网格 + 每张状态。
- 多张时顶部固定一条 warning：「这多张图会合并成同一份患者表单。请确认它们属于同一位患者；不同患者请分开识别。」

## 6. 边界与下一步

1. **心电图已接**：见 [心电图接入.md](心电图接入.md)。真实单 #1 现在能回填 `heart_rate / qtc / sinus_rhythm`；PR、QRS、电轴、SV1、RV5 仍只进「未回填」。
2. **逆向指标不自动填**：PT 活动度、D-二聚体、BNP 目前只进「未回填」；要接需要各自的字段和方向（低值异常/高值异常）。
3. **长单可能还要切块**：4MP 是折中；如果 6502px 的单子仍读不全，下一步做纵向切块（带重叠），复用现在的多图合并。
4. **没有患者身份校验**：多图只靠医生确认「同一患者」。不同患者的单子一起上传，会合并成一份表单——这是当前最大的使用风险，界面已有警告，但程序无法识别。
5. **耗时/费用**：每张 10–20 秒，8 张约 2–3 分钟；每张都会真实调用一次 qwen3-vl-plus。中途停止只中止当前请求，已完成的不会重复计费。
6. **冲突默认取第一张**：医生必须自己判断采用哪张；程序不会按日期/来源自动选。
